## 快捷搜索弹窗

快捷搜索默认启用，搜索首页会显示当前快捷键。点击提示旁的关闭按钮后，提示不再显示，快捷键仍可使用。

![搜索首页的快捷搜索提示](/images/product-search-home-cn.png)

SAG Wiki 运行期间，按 **macOS：⌘⇧Space** 或 **Windows：Ctrl+Shift+Space**，即可从其他应用唤起快捷搜索；也可以从菜单栏或托盘选择“快捷搜索”。关闭主窗口后仍可使用，完全退出应用后快捷键停止生效。

![快捷搜索弹窗](/images/product-quick-search-cn.png)

输入后自动搜索已有本地索引，最多展示 10 个匹配文件，左侧列表支持滚动。使用 **↑ / ↓** 选择、**Enter** 在主窗口打开对应原文，单击左侧文件或使用方向键时右侧同步预览高亮原文；**Esc** 关闭并返回之前的应用；点击弹窗外也会关闭。**⌘ / Ctrl+Enter** 或“完整搜索”可进入主窗口查看全部结果。

“深入检索”需要先配置 Jev，仅在点击按钮后运行。弹窗不会自动生成搜索总结。打开原文或完整结果时，主窗口保留弹窗实际使用的检索方式。

在 **设置 → 快捷键 → 快捷搜索** 中，可以启用或关闭全局快捷键。点击快捷键输入框录入组合键，再点击“应用快捷键”，会立即保存并生效；无需再次点击底部“保存设置”。如果快捷键已被占用，会显示错误，原快捷键保持可用。

## 快速搜索

输入文档中的词语即可开始本地搜索。快速搜索无需配置模型密钥，适合查找名称、术语和已知内容。

![搜索结果与原文高亮](/images/product-search-cn.png)

搜索结果按文件归组，点击结果在右侧阅读原文。原文左上角的返回按钮可回到搜索总结。点击“相关片段”可选择同一文件的命中片段；原文顶部的匹配导航可继续切换位置。文档操作菜单提供“打开文档”和在文件夹中显示的入口。

在上方输入框修改关键词并提交，即可再次搜索。点击左上角返回按钮可清空查询并查看最近搜索。

原文中当前选中的匹配会突出显示所在的整个段落。Markdown 在浅色主题下使用深色背景、浅色文字；HTML 使用段落轮廓标记，保留原文的文字和背景色，避免降低对比度。Markdown 原文按选中片段的位置高亮，即使语义搜索结果不包含搜索原词，也能看到选中段落。文内查找仍按输入的词语定位，并使用对应的段落标记样式。

Markdown 中的 HTML 表格会在搜索预览、快捷搜索和引用原文中渲染为表格，保留合并单元格和加粗格式。编辑时保留原始 HTML；明确放在代码块中的表格示例仍显示源码。

![HTML 表格的合并表头和数值格式](/images/product-html-table.png)

HTML 段落、标题和链接也会正常显示，并保留居中对齐与图片尺寸。相对路径的本地图片从文档所在目录加载，支持 PNG、JPEG、GIF、WebP 和 SVG；外部图片不会自动加载。编辑时保留原始 HTML，代码块中的 HTML 示例仍显示源码。

![README 中的本地 Logo、居中标题和链接](/images/product-readme-html.png)

## 阅读搜索结果

- 拖动结果列表与原文之间的分隔线调整宽度；鼠标或键盘切换文件后，会自动滚动到当前选中片段的高亮位置。
- 使用原文顶部的文内查找、相关片段和专注阅读按钮，集中查看命中内容。
- 大文档优先显示目标段落，其余内容逐步加载；窄窗口可通过返回按钮回到结果列表。

## 深入检索

先在模型设置中配置 Jev 服务、模型和 API Key，再选择深入搜索。使用完整问题描述需要查找的内容，例如：

```text
这个项目如何处理登录与权限？
```

SAG2 检索会召回候选原文，通过 Jev 判断证据相关性，按需扩展查找范围，再返回相关来源。它适合需要跨文件查找的问题。

![语义搜索结果按原文片段高亮](/images/product-search-semantic-cn.png)

## 两种搜索的区别

| 项目 | 快速搜索 | 深入检索 |
| --- | --- | --- |
| 输入 | 词语、名称、明确内容 | 完整问题或语义描述 |
| 执行 | 本地全文检索 | 本地索引与 Jev 服务 |
| 服务配置 | 无需模型密钥 | 需要 Jev 配置 |
| 输出 | 匹配文件与原文 | 与问题相关的证据来源 |

## 查看耗时

界面显示搜索用时和处理状态。问答中的工具耗时还包含工具请求本身的处理过程，比较不同入口时应同时核对问题、范围和检索配置。

## 搜索设置详解

入口：**设置 → 搜索设置**。先阅读 [技术科普](/zh/docs/sag2)，理解候选、扩展和最终结果的区别。

![自动总结和 SAG2 检索参数](/images/product-search-settings-cn.png)

### 搜索结果自动总结

默认开启。搜索有结果后，自动打开并展开“搜索总结”，根据问题和参考结果生成简短总结。点击左侧结果可阅读原文，点击“搜索总结”可返回总结。关闭自动总结或未配置回答模型时，默认打开第一个文件。

![搜索后默认打开总结](/images/product-search-summary-cn.png)

使用自动总结需要先配置[回答模型](/zh/docs/models)，可能产生对应服务费用。不要把总结用时与纯检索用时混为一项。

### 自动总结参考数量

默认 10 条，最小 1，没有固定最大值。决定最多取多少条搜索结果作为总结参考；当超过回答上下文预算时，应用会裁剪输入。增大数量不保证总结更好，也会增加输入量。

### SAG2 参数

| 设置 | 默认值 / 范围 | 作用与调整影响 |
| --- | --- | --- |
| 每轮候选数量 | 50 / 10–100 | 问答检索每轮的新候选上限。增大可扩大评分范围，也增加 Jev 处理量。桌面深入搜索固定为 100，不受此项改变。 |
| 扩展起点数量 | 10 / 1–20 | 每轮从评分结果中选择多少个尚未扩展的片段，作为继续检索的起点。更多起点会带来更多上下文与词项。 |
| 扩展词上限 | 20 / 1–500 | 控制从起点提取的词项和完整名称短语数量。增大可扩展查询，也可能引入更多无关候选。 |
| 扩展轮数 | 1 / 0–2 | 初次召回之后再扩展多少轮。0 为仅首次检索；1 为最多 2 轮；2 为最多 3 轮。没有新候选时提前结束。 |
| 返回片段数量 | 10 / 1–100 | 问答检索工具最终返回多少个片段。它不决定每轮召回数量。桌面深入搜索最多展示 100 个文件；CLI 可用 `-m` 指定输出上限。 |
| 片段目标字符数 | 512 / 400–12000 | 建库切分时的目标长度。保留完整句子与相邻上下文，长句可超过目标。修改后自动重建索引。 |

### 如何调整

先使用默认参数。在固定问题与文件范围下，一次只改一项，并对比原文是否覆盖问题所需事实及总耗时。

- 返回内容太多：先降低返回片段数量，不必同时减少候选范围。
- 需要跨文件补充事实：可以检查扩展轮数和起点数量。
- 单个片段缺少上下文：可以调整片段目标字符数，但需等待重新索引。
- 检索太慢：检查候选数量、扩展轮数和 Jev 服务耗时。

### 恢复默认参数

把六项 SAG2 参数恢复为 `50 / 10 / 20 / 1 / 10 / 512`。随后点击保存设置。此按钮不重置自动总结开关和总结参考数量；若片段长度发生变化，会触发索引更新。

### 轮数与请求数量

当前实现最多进行 3 轮 Jev 评分，本地最终排序不额外调用模型。同一轮候选过多时会按请求预算分批，保留完整候选；一个候选连同共享证据仍超出预算时，会明确报错而不截断原文。

因此，界面上的检索轮数不等于实际 Jev HTTP 请求数量。更大的候选、起点或片段可能增加批次与耗时。

## Conan 本地嵌入（core 集成）

Rust core 已提供本地 Conan ONNX 编码器和供融合使用的 top-50 检索函数，本次集成不增加桌面操作入口。编码器直接读取 1792 维的 `sentence_embedding`，将大于零的值打包为 224 字节，通过 sqlite-vec 对已存储的块向量做 Hamming 排名。块嵌入复用现有七天缓存，缓存键包含文本哈希与模型路径、revision。编码器按模型签名共享会话，poisoned 会话会在复用前销毁。

模型不打包，发现过程绝不触发下载。core 先查本地 Hugging Face 缓存中的 `onnx-community/Conan-embedding-v1`（`onnx/model_int8.onnx` 或 `model_int8.onnx`，以及 `tokenizer.json`），再查显式导入的组件。缓存目录依次取 `HF_HUB_CACHE`、`HF_HOME/hub`、`~/.cache/huggingface/hub`。调用方指定快照 revision 或本地 `main` 等 ref。缺模型时打印提示并返回空 Conan 腿，供调用方继续融合其余可用腿。WeMM 实时编码不在本次集成范围内。

显式组件导入接收已经下载的文件流和可信的大小、SHA-256：先暂存、校验，再原子安装不可变 revision。校验失败保留已有版本。发现已导入组件时也会校验完整性，不会自行选择或覆盖当前模型。

ONNX Runtime 使用动态加载。可用 `ORT_DYLIB_PATH` 指向原生库文件；未设置时依次搜索可执行文件同目录、其 `lib` 子目录、平台库路径环境变量（Linux 为 `LD_LIBRARY_PATH`，macOS 为 `DYLD_LIBRARY_PATH`，Windows 为 `PATH`），Unix 上最后搜索 `/usr/local/lib`、`/usr/lib`。原生库来自 [Microsoft ONNX Runtime 1.31.0 已发布版本](https://github.com/microsoft/onnxruntime/releases/tag/v1.31.0)：Linux x86_64 使用 `onnxruntime-linux-x64-1.31.0.tgz`；macOS、Windows 选择相应平台与架构的归档。Linux 库名为 `libonnxruntime.so`，macOS 为 `libonnxruntime.dylib`，Windows 为 `onnxruntime.dll`。x86_64 预编译库要求 AVX2，较老 CPU 可能发生 illegal instruction。macOS/Windows 原生加载：**未验证**。

与既有 Python bf16 块向量的六题对照：本地 int8 ONNX 模型在 Q1–Q6 的 top-50 集合重合数分别为 **47、49、47、48、48、49 / 50**，差异来自 int8 量化数值（约 33/1792 位翻转），不是 Rust 实现错误。验收标准为融合后 top-10 证据覆盖与 Python 腿一致、检索分保持 4.0/5：实测 Q1/Q3/Q4/Q5/Q6 证据集合完全相同，Q2 差一块边界证据但得分仍为 1.0，总分 4.0/5。回归测试按此标准断言。

切换模型句柄前，公开的兼容检查会对相同文本对应的浮点向量抽样比较：维度必须一致，平均余弦相似度必须至少为 0.9。检查失败时保留当前句柄，不改写已存向量，不自动重嵌旧块；空样本、零向量和非有限数值也会被拒绝。打包后的二值向量不能代替此处所需的浮点样本。

## 快/准检索与多腿融合

检索分快、准两档（检索配置 `mode`，默认快档）。

- **快档**：只用 SAG2 单腿，即原有深入检索行为，不变。
- **准档**：并行跑 SAG2 腿与向量腿（Conan；WeMM 缺模型时自动回落为 Conan + SAG2 两腿），每腿取 top-50，经 RRF（k=60）加每作者 top-5 配额融合，取最终 top-10。六题对照检索分 4.5/5。

**优雅降级**：任一腿失败（缺模型、向量表未建、ONNX 加载失败）时自动回落到可用腿，不中断检索；缺模型时不触发下载。

**检索旋钮**（检索配置）：关键词/向量权重默认 0.8/0.25，相似度阈值默认 0.2，候选池默认 50，融合参数 RRF k=60、每作者配额 5、每腿 top-50、最终 top-10。既有库首次打开时自动把旧默认 0.7/0.3 迁为 0.8/0.25，自定义权重不受影响。

**字面精确匹配**：检索另有一条字面匹配腿，对埋藏数字、人名等精确内容做字面命中，与 BM25 并行，命中并入候选池再融合。

**文件夹权重**：每文件夹可设权重（默认 1.0），检索时加入混合分数，高权重文件夹内容在平局时排前面。

**双档解析**：解析分快、准两档。快档用轻量文本抽取；准档在抽取后补布局与表格识别（Docling），表格内容可被检索到。

**增量同步**：批量导入有检查点续跑，中断后恢复不重复处理已完成文件；删除文件后其块从全文与向量索引清除，不再可检索。

**索引并行数**：设置 → 文件设置 → 索引并行数，默认 8，可设 1–64，下次索引任务生效，不重建已有索引。批量索引用有界工作池加内存预算背压，避免大批量导入占满内存。
